# SentFrom issuer checklist evidence map

Prepared 8 November 2026. Scope: `https://identity.sentfrom.ai`, `mail.sentfrom.ai`, direct Core ES256. This is an evidence map and a supplementary targeted I-54 execution, not a new full conformance run or admission decision.

The current [programme](https://github.com/agentlogin/reference/blob/8ce918578d21adde81567ee62058f1b4b710e7cf/trusted-providers/README.md) and [Core checklist](https://github.com/agentlogin/spec/blob/536c5d15738f45a3c2115884a0a43cdd28b06dd3/conformance.md) control. Each checklist group contains multiple obligations; a test pointer does not silently mark untested branches as passing.

**Evidence basis.** The beta.3 CI receipt reports 970 tests passed, zero top-level failures/skips. The actual issuer and PostgreSQL implementation/test trees are byte-equivalent to deployed reference `62c54330cca22a1ff0a61c4278431ca23457926d`; source bindings are recorded in [the application](README.md). The 8 November authenticated infrastructure readback identifies the same November 3 issuer deployment/image. No customer credentials or live mutations were used in this review.

**Important harness limitation.** The HTTP harness has explicit labels for 39 of these 57 items. Its fixture intentionally accepts an internal SKIP for the I-9 random-generation proof and may permit unavailable advisory evidence. Thus zero top-level test skips is not a claim of zero internal evidence gaps. The remaining items use concrete regression/contract/host tests or explicitly labelled source assessment. The HTTP fixtures use local development endpoints; they do not prove production DNS/TLS or all proxy/header behavior.

**Labels.** TESTED means the cited implementation scenarios ran in recorded passing suites, not that every production branch was executed. LIVE means the bounded anonymous read or historical live run stated. SOURCE/PARTIAL/HOST REVIEW makes residual coverage explicit; it is not a fabricated PASS or automatic nonconformance.

## Decision boundaries

Untested behavior is not automatically a Core violation. The programme nevertheless requires an evidence-based conclusion about each applicable item and no unresolved authority/disclosure defect. The operator should explicitly accept the stated source assessments or add focused tests where the residual uncertainty matters. This map does not certify security, deployment capacity or universal interoperability.

The current live quota policy explicitly publishes zero retention after Owner deletion. No new positive retention rule, second human onboarding prerequisite, external human approver or independent-protocol-reimplementation requirement has been added here.
